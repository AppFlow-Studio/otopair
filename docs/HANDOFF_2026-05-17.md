## 6. Methodology rules earned the hard way this session

1. **Verify domain claims against ground truth before flagging regressions.** N63/S63 mistake: the AI correctly returned "S63" for the M6 (which has S63), but the eval case was authored for the M550i (which has N63). The eval RUNNER was sending the wrong vehicle, not the AI being wrong. Always cross-check assertions against what was actually queried.

2. **The eval suite's `vehicle_vin_tail` defaults to "N96146"** (the test M550i, full VIN `WBAJS7C01LBN96146`). Cases that don't specify `vehicle_vin_tail` rely on this default per the JSON's `_doc` field. The original runner ignored the default → ran all 31 cases against most-recently-added (the M6). The runner now correctly resolves vin_tail → full VIN via a suffix index built from the user's owned vehicles.

3. **Don't dispatch infrastructure without integration awareness.** Wave 3 Days 1-4 shipped helpers, CI rules, eval cases — but NOTHING called the helpers from chat.ts. 4 days of "inert infrastructure" was the failure mode. The integration walk (commits `912ebe2` → `f8ee607`) fixed this AFTER Waleed caught it. Lesson: every "wave" dispatch should include "and wire it into the production code path" as a deliverable, not just "build the table + helper."

4. **Haiku is variance-prone enough that N=1 runs are noisy.** Same prompt, different output. The QA Review's ≥95% N=10 threshold spec exists for a reason. Don't draw conclusions from single runs.

5. **Convex auth header is type-dependent.** Deploy keys: `Authorization: Convex <key>`. User JWTs: `Authorization: Bearer <token>`. The codebase initially used `Bearer` everywhere — broken for deploy keys. Auth fix landed in `3782738`.

6. **Convex deploys push the entire `convex/` directory** state on the current branch. Hotfix branches off pre-Sprint commits are the correct discipline for prod (don't accidentally push Sprint 1-3 with a 1-line fix).

7. **Trace tool-call buckets are NOT a single `tool_uses` array.** The trace has three separate buckets: `data_tool_uses`, `state_tool_uses`, `terminal_tool_uses`. Eval-runner assertion logic must union all three.

8. **Subagent claims are not ground truth.** The original Day 4 eval-result analysis was full of false alarms because the underlying RUNNER was misconfigured. When a subagent reports "X is broken," verify by inspecting the artifact yourself before believing.

9. **Prompt-length increases are NOT free.** Adding 22 lines to stable.ts (+2.5% length) measurably degraded the eval suite by ~8% pass-rate. Every prompt change should go through Wave 1.5 protocol comparator.

10. **`debug_skip_persist: true` skips Wave 3 wire-ins by design.** The wire-ins live inside the `!skipPersist` gate in chat.ts. Eval runs use skip_persist=true; production turns use skip_persist=false. This is correct strangler behavior.
